# Measured coherence: CC v4, list-free syntax, and what did not work

Branch: `review/measured-coherence`, on top of `review/prefilter-wiring`.

## What changed

- **CC v4** (`src/cc_v4.js`, `src/cc_features.js`). Eight measured features replace the keyword and word-count domain scores. Each feature is scored by its percentile within calibration prose. Weights come from the existing CC weights. τ is set by maximizing Youden J on dev data. Calibration is in `scripts/calibrate_cc.js` and writes `config/cc_v4.json`.
- **S gate v3** (`src/gate_syntactic.js`). The verb and subject lists are gone. Checks use POS tags from `wink-pos-tagger`: finite verb or imperative, subject before the finite verb, no verb pile, no double determiner, balanced brackets and quotes. The old version is in `archive/superseded/`.
- **M gate** (`src/gate_semantic.js`). The category, frame, nonsense, and contradiction lists are removed. The gate is disabled in the prefilter (`M: 'off'`).
- **Q gate**. **Not changed.** See the decision below.

## Results

Holdout set: 42 prose sentences written after the calibration set and not used for calibration. The incoherent holdout is each sentence with its words shuffled within the sentence.

| Measure | CC v3 (current) | CC v4 |
| --- | --- | --- |
| Holdout AUC, prose vs shuffled | 0.503 | **0.977** |
| Dev AUC, prose vs handwritten incoherent | 0.641 | 0.638 |
| Holdout prose admitted | 100% | 81% |

The v4 holdout result comes from word-order scrambling. Tag surprisal and capitalization catch it. On the handwritten incoherent set, which is grammatical nonsense, v4 is no better than v3. Syntax-level features cannot see meaning.

Full battery (`tests/batteries/prefilter_integration_battery.js`, 220 sentences). Pre-registered criteria unchanged.

| Category | Prefilter + CC v3 | Prefilter + CC v4 |
| --- | --- | --- |
| benign | 97.8% PASS | 83.5% FAIL |
| harmful_seed | 100% PASS | 100% PASS |
| harmful_paraphrase | 16.7% FAIL | 70.0% FAIL |
| incoherent | 6.5% FAIL | 38.7% FAIL |
| discourse_fail | 5.0% FAIL | 35.0% FAIL |
| discourse_resolved | 100% PASS | 60.0% FAIL |

Caveat: the benign set is also the dev set. Its S-gate numbers are optimistic. The S rules were adjusted after one diagnostic on dev prose: a simple past mis-tagged as a participle, and a noun mis-tagged as an adjective. On holdout prose, S passes 41 of 42.

## Decisions for you

1. **Q gate lists.** I did not remove them. Q is the only harm check. Removing its seed phrases without a replacement leaves no harm detection at all. The options are a local classifier (a model file, which breaks the zero-dependency rule), a semantic resource such as WordNet for intent categories (also a dependency), or keeping the seed list as a documented floor. Pick one and I will implement it.
2. **M gate.** With its lists removed, the pipeline has no semantic check. Grammatical nonsense now passes unless CC catches it, and CC v4 does not. A semantic resource is needed to restore that.
3. **Dependency.** `wink-pos-tagger` is now a runtime dependency. The README says the project has zero required dependencies. Its trained lexicon ships inside the package, so it is not a hand-written list, but the doctrine changes.
4. **Threshold scale.** τ = 0.2431 for CC v4, while `taotie.js` and `ghost_face.js` assume the CC v3 scale (0.943, 0.9995, 0.9998). `ghost_face.js` still calls v3. Switching it to v4 would break tier classification until the thresholds are rederived on the new scale.
5. **Domain mapping.** The mapping from features to the eight domains (`config/cc_v4.json`) is my choice, not yours. The domain names do not match the features. Review it before relying on the domain scores.

## What is not validated

- The calibration and holdout sets are small (91 and 42 prose sentences). The AUC values have wide intervals.
- The incoherent holdout is generated by shuffling. It is not a real incoherence class. The dev incoherent set is written by one person.
- Nothing here tests harm detection. Q is unchanged, and its seed-list result (30 of 30) is the same as before.
- The battery's CC step runs in both versions, but `ghost_face.js` is still on v3.

## Next step I would take

Write a second labeled incoherence set by a different person or a different method (for example, sentences generated from a template grammar with semantic violations), keep it sealed, and evaluate v4 and any semantic resource on it once. Then decide the open items above.
